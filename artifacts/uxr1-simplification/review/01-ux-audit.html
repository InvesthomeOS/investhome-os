What’s broken

Structural UX debt, not missing features

The default mental model is dense, technical, and table-heavy. Visual card modes exist but are underused for inventory and projects — the surfaces operators live in every day.

Density

Table-first everywhere

Marketing lists, CRM contacts/companies, inventory units, sales lists, investors, admin, BI, and portals all default to spreadsheet layouts. High cognitive load for status scanning and matching work.

Fragmentation

Same person, three apps

Lead detail, CRM contact, and investor record model one human across separate UIs. Sales leads, CRM leads, and marketing leads create triple intake paths.

Clutter

Technical platform leakage

Data platform, flags, API clients, design-system spikes, BI explorer, and automation engines sit near daily OS navigation — overwhelming the “daily work” story.

Charts & clutter

Meaningful vs decorative

Chart audit verdict Source: 01-current-ux-audit.md
Location Types Verdict

Older executive / BI domains Donut, Funnel, placeholders Thin data → decorative risk
CRM / Sales / Marketing strips Line, Bar, Sparkline, Funnel Generally meaningful
Admin design-system / TailAdmin All chart types Demo only — not product

Unsupported pattern

Charts without definition, time window, source endpoint, drill-down, or an honest empty state become noise. Donuts and funnels should only remain where intentional and contracted (see chart design policy).

Pain for sales & marketing

Who lives in the product daily

Daily operators pay the tax of a platform OS

Sales and marketing teams need a short path from lead → match → close / nurture. Today they navigate dual rails, progressive-disclosure failures on create forms, and status grids that expose every dimension at once.

  • Sales: Public lead → Sales board → lead-centric detail with many tabs → optional CRM conversion → inventory match / hold.
  • Marketing: Workspace dashboard → 12-step campaign wizard → audiences → channels → attribution, while a parallel G6 shell still exists.
  • Inventory: Filter tree + unit table with 6+ status dimensions visible simultaneously.
  • Forms: Lead / investor / inventory / project creates bury essentials under advanced fields (UTM, accreditation, lat/long, ~15 financials).
  • Nav load: OS sidebar + CRM ~18 + Marketing ~30 + separate portal/company shells.

What stays · what must change

Preserve backends; simplify UI

Stays on backend

Do not delete modules, tables, or APIs

  • Domain APIs, schemas, and stage enums (Sales opportunity stages)
  • CRM / Marketing / Finance / Inventory capabilities
  • Platform G15, BI internals, automation engines (permission-gated)
  • Portal & investor data services
  • Redirect + archive strategy instead of hard deletes

UI must change

Information architecture & daily UX only

  • Unify person identity under Customers
  • One commercial board: Sales (CRM pipeline secondary)
  • Collapse Marketing to home + Content Studio; demote deep channels
  • Visual-first Inventory & Projects
  • Chart contracts + honest empties; hide platform from normal nav
  • Progressive disclosure on create/edit forms
